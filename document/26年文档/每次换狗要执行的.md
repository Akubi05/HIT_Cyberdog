• 这是 SSH 登录失败：
  Permission denied (publickey,password)
  意思是脚本尝试用：
  mi@192.168.96.19
  登录机器狗，但 SSH 公钥没通过，密码登录也没成功或没有被正确输入。
  你可以按这个顺序排查。
ssh-keygen -f '/home/luke/.ssh/known_hosts' -R '172.20.10.2'

  1. 先手动 SSH 登录确认账号密码

  在你的电脑上执行：

  ssh mi@192.168.96.19

  如果提示：

  Are you sure you want to continue connecting
  输入：yes
  然后输入密码：123
  注意密码输入时终端不会显示字符，这是正常的。

  2. 如果手动登录成功

  说明 IP、用户名、密码没问题。你的脚本失败大概率是因为脚本不能交互输入密码。

  解决方式有两种。

  推荐：配置 SSH 免密登录：

  ssh-copy-id mi@192.168.96.19
  ssh-copy-id mi@192.168.1.102
  提示输入密码时输入：

  123

  之后再测试：

  ssh mi@192.168.96.19

  如果不再要求密码，就可以重新运行你的 stage4 脚本。

  3. 如果 ssh-copy-id 不存在

  可以先生成本机 SSH key：

  ssh-keygen -t ed25519

  一路回车即可。然后再执行：

  ssh-copy-id mi@192.168.96.19

  4. 如果手动登录也失败

  检查这些点：

  ping 192.168.96.19

  确认网络能通。

  确认用户名确实是：

  mi

  确认密码确实是：

  123

  确认机器狗上允许 SSH 密码登录。需要在机器狗上检查 /etc/ssh/sshd_config，至少要
  允许：

  PasswordAuthentication yes

  改完后重启 SSH 服务。

  5. 如果之前连过同一个 IP，但设备换了

  可能有 known_hosts 冲突。现象通常会包含 REMOTE HOST IDENTIFICATION HAS
  CHANGED，如果你看到这个，再执行：

  ssh-keygen -R 192.168.96.19
  ssh mi@192.168.96.19

  你现在最该做的是先手动跑：

  ssh mi@192.168.96.19

  能登录后，再配置：

  ssh-copy-id mi@192.168.96.19

  然后重新运行你的脚本。
