问题不是相机没起来，是你混用了两套命名空间。

  你这套手动启动命令：

  ros2 launch realsense2_camera on_dog.py &
  ros2 launch camera_test stereo_camera.py &

  实际生成的是这些节点：

  /camera/camera
  /stereo_camera

  实际图像 topic 是：

  /image_left
  /image_right
  /image_rgb

  所以这些才是正确命令：

  ros2 lifecycle set /camera/camera configure
  ros2 lifecycle set /camera/camera activate

  ros2 lifecycle set /stereo_camera configure
  ros2 lifecycle set /stereo_camera activate

  ros2 topic hz /image_left

  你写的这些：

  ros2 lifecycle set /mi_desktop_48_b0_2d_5f_b4_22/camera/camera configure
  ros2 lifecycle set /mi_desktop_48_b0_2d_5f_b4_22/stereo_camera configure
  ros2 topic hz /mi_desktop_48_b0_2d_5f_b4_22/image

  对应的是 CyberDog 系统命名空间里的节点/topic，不是你手动 launch 出来的那套。当
  前远端我看到 /mi_desktop_48_b0_2d_5f_b4_22/image 没有 publisher，只有订阅者，
  所以测它不会有输出。

  另外注意两点：

  ros2 lifecycle get /camera/camera
  ros2 lifecycle get /stereo_camera

  如果已经是 active [3]，就不要再 configure，因为 active 状态下只允许 deactivate
  或 shutdown。

  如果你一定要让手动启动也走 /mi_desktop_48_b0_2d_5f_b4_22 前缀，要启动时就带
  namespace，例如：

  NS=/mi_desktop_48_b0_2d_5f_b4_22

  ros2 launch realsense2_camera on_dog.py camera_name:=$NS/camera &
  sleep 4
  ros2 lifecycle set $NS/camera/camera configure
  ros2 lifecycle set $NS/camera/camera activate

  ros2 launch camera_test stereo_camera.py namespace:=$NS &
  sleep 4
  ros2 lifecycle set $NS/stereo_camera configure
  ros2 lifecycle set $NS/stereo_camera activate

  然后用 ros2 topic list | grep image 看实际 topic 名，不要假设一定是 $NS/
  image。当前这套 stereo_camera.py 正常情况下是 /image_left 这一组。

# 问题4
```
mi@mi-desktop:/$ ros2 topic hz /mi_desktop_48_b0_2d_5f_b4_22/image
  没有结果 . 我已经打开了ros2 run camera_test camera_server --ros-args -r
  __ns:=/mi_desktop_48_b0_2d_5f_b4_22
```

• 原因有两个：

  1. 只跑 camera_server 不会自动发布 /mi_desktop_48_b0_2d_5f_b4_22/image，还要调
     用：

  ros2 service call /mi_desktop_48_b0_2d_5f_b4_22/camera_service protocol/srv/ CameraService "{command: 9, width: 640, height: 480, fps: 0}"

  我刚才调用后返回成功：

  result=0, code=0

  2. 你这台 Galactic 的 ros2 topic hz 对这个 topic 不可靠。它创建的 _ros2cli 订
     阅端是 BEST_EFFORT，而 /image publisher 是 RELIABLE。这个版本的 ros2 topic
     hz 又没有 --qos-reliability reliable 参数，所以会出现“topic 有数据但 hz 不
     打印”。

  我用可靠 QoS 的 Python 订阅器实测到了数据：

  /mi_desktop_48_b0_2d_5f_b4_22/image: 640x480, bgr8, step=1920
  samples 245, hz 25.56

  所以当前 /mi_desktop_48_b0_2d_5f_b4_22/image 是在发布的。验证时不要用这个 ros2
  topic hz 判断，改用可靠 QoS 订阅器，或者用你的程序订阅时设置 RELIABLE。

# 问题5

mi@mi-desktop:/$ ros2 topic hz /mi_desktop_48_b0_2d_5f_b4_22/image
  没有结果 . 我已经打开了ros2 run camera_test camera_server --ros-args -r

方法如下，不改你代码。

  Python rclpy

  from rclpy.qos import QoSProfile, QoSReliabilityPolicy, QoSDurabilityPolicy
  from sensor_msgs.msg import Image

  qos = QoSProfile(depth=10)
  qos.reliability = QoSReliabilityPolicy.RELIABLE
  qos.durability = QoSDurabilityPolicy.VOLATILE

  sub = node.create_subscription(
      Image,
      "/mi_desktop_48_b0_2d_5f_b4_22/image",
      callback,
      qos
  )

  C++ rclcpp

  #include <rclcpp/rclcpp.hpp>
  #include <sensor_msgs/msg/image.hpp>

  auto qos = rclcpp::QoS(rclcpp::KeepLast(10))
    .reliable()
    .durability_volatile();

  sub_ = node->create_subscription<sensor_msgs::msg::Image>(
    "/mi_desktop_48_b0_2d_5f_b4_22/image",
    qos,
    callback);

  命令行快速验证，不用 ros2 topic hz

  Galactic 的 topic hz 不能指定 reliable。可以临时用 Python 测：

  python3 - <<'PY'
  import time, rclpy
  from sensor_msgs.msg import Image
  from rclpy.qos import QoSProfile, QoSReliabilityPolicy, QoSDurabilityPolicy

  topic = "/mi_desktop_48_b0_2d_5f_b4_22/image"

  rclpy.init()
  node = rclpy.create_node("reliable_image_probe")

  qos = QoSProfile(depth=10)
  qos.reliability = QoSReliabilityPolicy.RELIABLE
  qos.durability = QoSDurabilityPolicy.VOLATILE

  count = 0
  t0 = time.time()

  def cb(msg):
      global count
      count += 1
      if count == 1:
          print(msg.width, msg.height, msg.encoding, msg.step)

  node.create_subscription(Image, topic, cb, qos)

  while time.time() - t0 < 5:
      rclpy.spin_once(node, timeout_sec=0.1)

  print("count:", count, "hz:", count / 5.0)
  rclpy.shutdown()
  PY

  核心就是：订阅 /mi_desktop_48_b0_2d_5f_b4_22/image 时 QoS 设成 RELIABLE +
  VOLATILE。


# 问题6 

怎么用topic hz 它?


• 在这台 ROS 2 Galactic 上，ros2 topic hz 不能正确测 /
  mi_desktop_48_b0_2d_5f_b4_22/image，因为它不能指定 RELIABLE QoS，而这个 topic
  的 publisher 是 RELIABLE。

  你可以先确认：

  ros2 topic hz -h

  如果帮助里没有 --qos-reliability，那就没法用 topic hz 测它。

  如果你的环境支持 QoS 参数，命令应是：

  ros2 topic hz --qos-reliability reliable /mi_desktop_48_b0_2d_5f_b4_22/image

  但你狗上的 Galactic 版本大概率不支持，所以只能用 Python 小脚本测频率，或者改一
  个可靠 QoS 的订阅程序来测。ros2 topic hz 本身不适合这个 topic。
